## 2. 採用する方式

### 目標 2: Codex レビューを毎回確実に起動する → 説明文方式（設定変更なし）
1. モネが PR を作るとき、説明文に `@codex review` を**1 行**入れる（実証済み。設定も追加課金も不要）
2. 修正を push した後は、修正したセッション（Auto-fix 側またはモネ）が、**人間のアカウントで** `@codex review` を 1 回コメントする（push では自動再レビューされないため）
3. **確認とフォールバック**: PR 作成の 60 秒後に、Codex の要約コメント（`chatgpt-codex-connector[bot]`）が対象 head SHA で出ているか確認する。出ていなければ、人間のアカウントで `@codex review` を **1 回だけ**コメントする（2 回目は依頼せず停止）
4. Actions のボットによる依頼は使わない（起動を実証できなかったため）。PR #5 のワークフローは、アムの確認のうえ、マージしない

### 目標 1: Auto-fix を毎回手動で ON にしない → スケジュールタスク方式（要・1 回の承認操作）
- GitHub トリガーのスケジュールタスクを 1 つ作る。`claude/` ブランチの PR が opened になると、新しいクラウドセッションが自動で始まる
- そのセッションに「この PR を監視して、レビュー指摘と CI 失敗を修正する」と指示する（下の 4 章のプロンプト）
- 作成はブラウザで 1 回だけ（claude.ai/code/routines）。モネの会話からは作れない
- 未確認: 起動したセッションが実際に PR を監視して修正できるか。作成後の 1 回の試験 PR で確認する

## 3. 1 回の依頼から進める順番（v2）

1. **開始確認**: リポジトリが sandbox、main の状態、オープン PR、禁止事項
2. **作業**: `claude/` ブランチで合成テストだけ変更。`npm test`
3. **PR 作成**: base は main。説明文に `@codex review` を 1 行入れる。PR URL・head SHA・時刻（JST）を記録
4. **自動で起きること**: Codex が約 20 秒で開始。スケジュールタスクがセッションを起動（作成済みの場合）
5. **レビュー判定**: Codex の正式レビュー（`chatgpt-codex-connector[bot]`、対象 head SHA）を確認。要約コメントだけでは「レビュー済み」と数えない
6. **修正**: 明確な指摘だけ。回帰テストを先に足し、最小修正を push。`npm test` と CI を確認
7. **再確認**: 修正した head に対して、`@codex review` を 1 回コメントして、再レビューを確認
8. **終了**: マージしない。監視を止める。PR は残すか、計画に従いクローズ

### 停止条件（1 つでも該当したら停止）
- sandbox 以外のリポジトリ・UtaMIX・Netlify・本番が関わる
- Codex が 10 分以内にレビューを返さない（原因は断定しない）
- 指摘が曖昧・複数・認可仕様に不確実性がある
- 修正が 1 サイクルで明瞭に終わらない
- マージ・追加課金・権限拡大が必要になる
- `@codex review` を 2 回以上依頼する必要が出た
