# モネを唯一の入口にする：Claude × Codex サンドボックス手順（v1）

この文書は **amukutsurogiwork-oss/ai-collab-sandbox** 専用。実行コードではなく、今後の共同試験のための運用手順。
目的は「利用者→モネ1回の依頼→ClaudeのPR→Codexの独立レビュー→Claudeの修正→CI→結果報告」を、GitHub上の証拠で繰り返し検証できるようにすること。

## 既に確認されたこと / 未確認のこと

- PR #1 と PR #2 で Codex の `chatgpt-codex-connector[bot]` が private-document 認可不具合を P1 として指摘した。
- モネ（Claude）が回帰テストを追加して修正し、PRごとのCIを通した。PR #1/#2はクローズ済み・未マージ。
- PR #2 は Codexレビュー→モネ返信→修正push の時系列が成立した。ただし Auto-fix を有効にした時刻は Claude セッションの申告であり、第三者が独立確認したものではない。
- **未確認:** Auto-fix の起動が毎回成功すること、無人での継続実行、他のリポジトリでの再現性、ChatGPT通常チャット（アム自身）の自動参加。
- Codexのレビュー機能とChatGPT通常チャットは別。ここで Codex を「アム側のレビュー担当」と呼んでも、通常チャットの判断・対話が自動で中継されるわけではない。

## 役割と禁止事項

- 利用者は **モネに1回依頼**する。モネがタスク、PR、レビュー待ち、Auto-fixを扱う。
- モネは変更・テスト・PR作成・修正を担当。Codexは**レビューのみ**とし、`@codex fix`やCodexからのコミット・pushを求めない。
- 実験対象はこの公開サンドボックスだけ。UtaMIX、ゆうひ、ぽこぽこ、Netlify、本番環境、ほかのGitHubリポジトリにアクセス・変更しない。
- 実データ、非公開リポジトリの内容、秘密情報、トークン、音源を持ち込まない。
- `main`直接push・マージ・自動マージ・デプロイ・課金API・追加クレジットの購入・権限拡大は禁止。
- 有効にしてよいのは既存プランの範囲のClaude Code Cloud/Auto-fixとCodexレビューだけ。追加課金や有料設定が必要なら停止。
- Auto-fixはPR単位の機能であり、無制限に繰り返す機構ではない。**1修正サイクルを基本**とし、不明点・複数の指摘・想定外のCI問題は停止して報告する。

## 1回の依頼から進める順番

1. **開始確認**：リポジトリがこのサンドボックスか、`main`の状態、オープンPR、課金・連携・デプロイの禁止条件を確認。他の作業中PRを変更しない。
2. **作業**：独立`claude/`ブランチで指定された合成テストだけ変更。原則`npm test`を実行し、変更内容と意図をまとめる。新しいテスト目的を勝手に広げない。
3. **PR作成**：`main`をbaseとする未マージPRを1件作成。PR URL・head SHA・作成時刻（JST）を記録。PRの公開自体がCodex自動レビューを開始する可能性がある。
4. **Auto-fixを有効化**：Claude Code Cloud の対象PRでAuto-fixをONにして、実際のUI/セッションから有効化を確認。可能な証拠（画面表示・セッションの記録・確認時刻）を残す。**有効化を確認できなければ次に進まず停止**。
5. **Codexのレビューを判定**：
   - Auto-fix有効化 **後** に、`chatgpt-codex-connector[bot]` による正式なレビューが対象head SHAに届いた場合、追加依頼せず受信・反応を確認する。
   - 有効化前にしかレビューがない、またはレビューがない場合は、対象PRのトップレベルコメントで `@codex review` を**最大1回だけ**依頼する。既存コメント・レビューを確認してから実行し、重複依頼はしない。
   - 要約コメントは「レビューが正式に投稿された」証拠として数えず、GitHubのreviewイベント、review receipt、レビュー対象commitを照合する。Codexが反応しなければ原因を断定せず停止。
6. **Auto-fix反応を確認**：新しいレビューの投稿者・時刻・対象SHA、Claudeセッション側の通知・反応を区別して記録。botレビューがGitHubに存在しても、Claudeへ通知されたとは断定しない。反応がなければ無理に修正を始めず停止。
7. **修正**：明確な指摘の場合だけ、モネが新しい回帰テストを追加し、最小修正をpush。意図的な不具合は公開用コードに流用しない。修正後に`npm test`とGitHub CI結果を確認する。
8. **終了**：成功時はAuto-fixを停止。マージはせずPRを残すか、実験計画に従ってクローズする。Claudeからの追加pushとCodexの追加レビューが無限ループしないようにする。

## 停止条件（どれか1つで停止）

- 自分のPRではない／対象リポジトリの識別不能／期待するhead SHAと異なる。
- Claude GitHub App、Codex接続、Auto-fixの有効化が確認できない。
- Codexのレビュー受信が確認できない、botレビューがClaude側へ届かない、既に依頼したレビューへの重複依頼が必要。
- 認可仕様に不確実性がある、テストが失敗した、変更差分が想定外、1回で明瞭に修正できない。
- main変更・マージ・追加課金・別リポジトリ・公開設定・新規App権限が必要。

## 報告様式

次を**確認済み・セッション申告のみ・未確認**の3区分に分け、時刻はJSTとする。

| イベント | GitHub/Claudeの根拠 | 時刻 | 状態 |
| --- | --- | --- | --- |
| PR作成 | URL, base/head SHA | | |
| Auto-fix有効化 | セッションまたはUIの記録 | | |
| Codex要約コメント | URL, bot名 | | |
| Codex正式レビュー | review URL, author, reviewed SHA | | |
| モネの受信・対応 | セッション記録, 返信URL | | |
| 修正と回帰テスト | commit SHA, 差分 | | |
| CI | workflow run URL, 結果 | | |
| Auto-fix停止 / マージ状況 | セッション・GitHubの記録 | | |

## 公式機能上の注意

- Claude Auto-fixはGitHub Appが対象リポジトリに必要で、クラウドPRのメニューまたはモバイル指示からPRごとに有効化する。受信するレビューとCIイベントに対応できるが、あいまいな指摘では確認待ちになる。
- Codexは `@codex review` でレビューを依頼できる。追加の修正依頼（`@codex fix`）はここでは使用しない。
- GitHubイベントを使うClaude Code scheduled taskは一部のPRイベントで別セッションを起動できるが、既存Auto-fixの常設代替や「この通常ChatGPTチャットと自由に会話する機能」と同一ではない。今回は新規の外部自動化・トークンを導入しない。
