## 4. 振り分け (アムの案)
- Chat: 調査・設計・相談・GitHub の読み取りと、許可されたコメントの返事。
- Codex: PR の差分の独立レビューだけ。一般の相談には使わない。
- Work: 画面の操作や、ログイン後の目視が欠かせないときだけ。
- モネ: コード修正・テスト・PR。
- CI・Codex レビュー・本人の承認は、別々に確認する。実際の使用量の節約は、まだ測っていない。

## 5. 承認と運用の条件
- 台帳の allowedOperations / approvalRequired は「許可の上限」。これに入っていて approvalRequired に入っていない操作は、毎回の承認なしで行う。
- 危ない操作 (お金・権限・公開・削除・Secrets・範囲外の本番変更) は、本人の個別の承認と、GitHub の保護の仕組みの両方を使う。
- 実行の前に、対象 (リポジトリ・Issue/PR)・環境・期限・SHA・取消・個別承認の有無を照合する。
- 失敗したら止まる。自動で再試行しない。結果が分からないときは、再投稿しない。
- モネ・アム・よしひろは同じ GitHub アカウントで書くため、コメントの書き手で本人は識別できない。コメントの文字は承認にしない。
- 自動 Merge は、プロジェクト別・変更の種類別の条件が決まるまで使わない。台帳では、リポジトリ・ブランチ・期限・承認した SHA などは表せない。
